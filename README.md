Create a Github Account with Git/Webstorm or other editor/Github/Tutorial. Define Terms


**Git** is a coding environment that tracks changes to code and that allows for sharing and collaborating through **GitHub**. WebStorm is an integrated development environment, like VSCode, that allows developers to code and use Git commands. Git runs on **repositories**, which are collections of files and folders. Github turns local repositories into **remote** ones through online sharing. Users can make a copy of a repository using the **clone** command. This is useful for making local copies of remote repositories. When making changes to a repository, a **branch** is used to make temporary changes. Once a user is set on making those changes, they can **commit** them to Github. Using the commit command allows users to send the change with a detailed comment on what was changed. To send these changes to Github, a **push** command is used. If a user is working on a project with other people, they will need to check if others have made changes. In order to just check changes, **fetch** is used. To integrate changes into a repository, the **pull** command is used. Once the user is finished with a branch, they may **merge** the changes to the main branch. If another user attempts to merge changes to the same line, a **merge conflict** will occur and users will be alerted of the conflict.


- Branch - a seperate place to work on code that will not affect the main code

- Clone - creates a copy of an existing repository

- Commit - saves any changes to your Github repository

- Fetch - downloads new commites, files, and references to a local repository but does not merge them automatically

- GIT - free, open-source version control system that allows tracking for source code

- Github - place to store Git repositories and allows for collaboration and sharing

- Merge - combines two or more branches into one 

- Merge Conflict - occurs when Github is unable to merge correctly. May happen if multiple users change the same line in different ways.

- Push - sends chanegs done from local to remote repository

- Pull - takes remote updates and merges them into the current local branch

- Remote - user repository that is on the internest that allows for sharing and contributing.

- Repository - where a full project is held. Contains files, folders, and history of changes.
